## 1. 产品定位

这是一款**忠实重制**：六边形格子上的限步连锁解谜。玩家侧对齐原作；架构按 Godot 重写，不抄 Unity 单例与场景生命周期。

原作玩法一句话：点击原子核，沿六向放出中子；中子碰到其他核会继续引爆。在有限步数内让所有原子坍缩。

概念来源（致谢，不是要做的克隆对象）：[Quantum Splitter](https://olivierguillaume.itch.io/quantum-splitter)。

### 1.1 玩家能玩到的

- 主菜单：Campaign / Custom 切换、关卡格、静音、退出
- 正篇 40 关 + 2 张自定义图（打进包内 JSON，游戏内无编辑器）
- 存档：已通关列表；未通关按关卡表顺序最多 3 个可进；已通关随时可重玩
- 局内：关卡名、剩余步数、Completed / Failed；约 2 秒后自动进下一关或重开；可立即重开、回菜单
- 平台：桌面 + 网页。自定义关不从玩家本地选文件。不为手机单独做布局，网页端只要点得动、拖得动

### 1.2 明确不做

- 模组、多模式框架、联网
- 游戏本体内的关卡编辑器（编辑器是同工程 EditorPlugin，不进导出包）
- 新原子类型、新胜负条件、重做正篇谜题
- 换新视觉
- 把 Angela Hewitt 的录音写成硬依赖

### 1.3 给以后留的缝（现在只定合同）

- 原子类型、中子方向用稳定字符串 ID 注册，不写死 `0..5`
- 关卡 JSON 带 `schema_version`，未知字段忽略并警告，未知类型在游戏中拒绝加载
- 盘面模拟与显示分离；局外插件与游戏跑同一套模拟

## 2. 词汇表

| 词 | 含义 |
| --- | --- |
| 格子 / 盘面 | 奇行右偏的 offset 六边形网格（odd-r）。逻辑 y 增大为「上」，与原作 Unity 2D 一致 |
| 原子 | 占一格。有核、0～2 层轨道、若干中子、一种类型 |
| 核 | 原子中心。玩家可点的核会释放；飞行中子碰到核会触发释放（不耗步） |
| 中子 | 沿六个主方向之一作直线运动的粒子 |
| 轨道 | 中子停在核周围的环。单层用中轨，双层分内轨/外轨 |
| 释放 | 把当前最外层轨道上的中子全部发射出去 |
| 坍缩 | 原子再无轨道可放：核消失，从盘面上移除 |
| 步 | 玩家主动释放一次消耗 1 步。拖动、连锁、捕获不耗步 |
| 反应 | 场上还有飞行中子的阶段。此时不能操作原子 |
| 捕获 | 捕获型原子用虚线轨道接住外来中子，中子改挂到该原子上 |
| 纠缠 | 同一 `group` 的纠缠原子，一次释放会同时释放组内尚未坍缩的成员 |
| 包 / pack | 一组有序关卡（`campaign` 或 `custom`） |

## 3. 玩家流程

```text
启动 → 主菜单
         ├─ 切换 Campaign / Custom
         ├─ 点关卡格 → 进入该关
         ├─ 静音
         └─ 退出

局内 WAITING → 点核释放（耗步）或拖可移动原子（不耗步）
            → REACTING（中子飞行、连锁、捕获）
            → 中子全部结束后：
                 全部坍缩 → WIN（Completed!，约 2s 进下一关，Campaign 记通关）
                 未清完且步数 > 0 → 回到 WAITING
                 未清完且步数 = 0 → LOSE（Failed!，约 2s 重开本关）
            随时可立即重开、回菜单
```

胜负节奏**完全按原作**：不增加「必须点 Next / Retry」的停顿。立即重开会打断 2 秒延迟。

通关后 `currentLevel` 加 1；超过该包末关则回到第 0 关。Custom 不通关存档。

## 4. 盘面几何

### 4.1 坐标系

- 存储：整数 `(x, y)`，与原作 `Maps.json` 相同
- 布局：**odd-r**。偶数行（`y % 2 == 0`）不偏移；奇数行向右偏半格
- 合法格：
  - `x >= 0`，`y >= 0`，`y < height`
  - 偶数行：`x < width`
  - 奇数行：`x < width - 1`（奇数行少一格）
- 逻辑世界坐标（y 向上，单位与原作一致）：

```text
spacing = (width >= 6 或 height >= 5) ? 1.8 : 3.0
wx = (y % 2 == 0) ? x * spacing : x * spacing + spacing / 2
wy = y / 2 * √3 * spacing
```

盘面在视图中居中。Godot 2D 的 y 向下只允许出现在**表现层**；模拟层禁止用屏幕像素或 Godot `position.y` 当规则真相。

### 4.2 中子方向

六个主方向，权威 ID 如下。旧数据数字只出现在一次性转换里。

| ID | 旧数字 | 逻辑向量（y 向上） | 说明 |
| --- | --- | --- | --- |
| `W` | 0 | `(-1, 0)` | 左 |
| `NW` | 1 | `(-1, √3)` | 左上 |
| `NE` | 2 | `(1, √3)` | 右上 |
| `E` | 3 | `(1, 0)` | 右 |
| `SE` | 4 | `(1, -√3)` | 右下 |
| `SW` | 5 | `(-1, -√3)` | 左下 |

飞行速度：逻辑单位 **6 / 秒**（原作 `Rigidbody2D` 速率）。向量必须归一化后再乘速度。

## 5. 核心规则

### 5.1 状态机

| 状态 | 可做的事 |
| --- | --- |
| `waiting` | 点可释放原子、拖可移动原子、重开、回菜单 |
| `dragging` | 跟随指针；松手吸附或退回。反应碰撞不结算 |
| `reacting` | 只跑模拟与表现；忽略点核/拖动 |
| `win` / `lose` | 显示文案，约 2 秒后自动切关或重开 |

不允许在 `reacting` 中操作原子。拖动只发生在 `waiting`。

### 5.2 步数与胜负

- 开局步数 = 关卡 `steps`
- 仅当玩家对**可点爆**原子执行释放时 `steps -= 1`（对应原作 `DoRelease`）
- 中子撞核引发的释放、纠缠连带释放、捕获，都不扣步
- `reacting` 在场上飞行中子数为 0 时结束，然后判定：
  1. 盘面上不存在未坍缩原子 → 胜
  2. 否则若 `steps > 0` → `waiting`
  3. 否则 → 负
- 坍缩时原子从盘面移除。判定「还有没有未坍缩原子」以运行时盘面为准，不是以开局列表为准

### 5.3 释放与轨道

原子有 1 或 2 层轨道，层数 = 关卡数据里 `orbits` 数组长度。

- 单层：一层中轨，中子按方向摆在中轨半径上。释放一次后坍缩
- 双层：`orbits[0]` 内轨，`orbits[1]` 外轨。先释放外轨，再释放内轨，然后坍缩
- 已坍缩则忽略后续释放
- 释放时该层所有中子同时进入飞行，并加入「在飞清单」

表现上，被释放的实线轨道向外扩大并淡出（原作约 0.1s 间隔、持续约 5s 的缩放淡出）。这只影响画面，不影响碰撞。

### 5.4 中子碰撞（规则层）

中子是确定性运动，不用物理引擎当真相。每一逻辑帧（或连续 TOI 扫描）按时间推进，命中用圆–圆、圆–盒检测。

命中优先级与对象：

1. **捕获轨道**（仅当目标当前可捕获）：中子被该原子捕获，离开在飞清单
2. **核**：对该原子执行「非玩家释放」（不扣步），中子销毁
3. **出界 / 墙**：中子销毁

同一中子在同一时刻只处理一个结果。自释放：刚从某原子放出的中子，在离开该原子核半径之前，**不**与该原子碰撞（避免立刻打到自己）。

同帧多个事件的次序（必须稳定，插件与游戏一致）：

1. 撞击时刻更早的先处理
2. 时刻相同则比中子的稳定 ID（生成顺序）
3. 再比目标原子的盘面坐标 `(y, x)`

墙：由当前盘面格子的逻辑包围盒外扩得到，外扩量对齐原作场景四边墙（约在相机可见区边缘）。中子中心圆一旦与墙碰撞盒相交即销毁。不要依赖 Godot 物理材质。

参考半径（原作 prefab，导入精灵后若缩放变了，以**画面上与原作一致**为准则微调，并写成常量）：

| 对象 | 原作半径（Unity 局部） |
| --- | --- |
| 中子 | 0.091 |
| 核 | 0.189 |
| 原子根触发器 | 0.363 |
| 捕获虚线轨道 | 0.680 |

规则层用：中子圆 vs 核圆 → 引爆；中子圆 vs 捕获轨道圆 → 捕获。非捕获原子的实线轨道**不**挡中子。

### 5.5 玩家操作

| 类型 | 按下 | 拖动/松开 |
| --- | --- | --- |
| `normal`、`entangled` | 释放最外层，扣 1 步，进入 `reacting` | 无 |
| `movable`、`entangled_movable`、`catching_movable` | 开始拖 | 放到空的合法格则占新格，否则退回原格。不扣步、不释放 |
| `catching` | 无规则效果（仅可有核的高亮） | 无 |

**可移动原子不能点爆。** 移动不耗步。40 关按此设计，禁止改成「点一下也放中子」。

悬停：可操作且未坍缩时，核略放大（约 1.1 倍）。可点爆原子改用高亮色；可移动原子颜色不变。纠缠核用组颜色。

拖动吸附：把指针位置变到逻辑坐标再 `world → (x,y)`。目标格必须合法且空。反应进行中不能开始拖。

### 5.6 捕获

- 仅 `catching`、`catching_movable` 在「仍可捕获」时用虚线轨道接中子
- 被接住的中子停止飞行，方向取反（原作 `Bounce`，为以后再释放做准备），挂到该原子中轨
- 捕获窗口：自**该原子第一次**接到中子起 **0.1 秒**内仍可继续接（对齐原作延迟改 type，允许多中子同时入轨）
- 窗口结束：`catching` → `normal`，`catching_movable` → `movable`；虚线轨道换成对应实线
- 变成 `movable` 之后仍然**不能点爆**，只能再被连锁打到核上才释放
- 捕获不扣步

### 5.7 纠缠

- `entangled` / `entangled_movable` 必须带正整数 `group`（原作关卡用 1、2、3）
- 任一成员被释放（玩家点或中子撞核）时：组内所有尚未坍缩、尚未列入本轮释放集合的成员立刻释放
- 玩家只扣 **1** 步（点下去的那一次）。连带释放不扣步
- 可移动纠缠体：玩家只能拖，不能点爆；被组员或中子释放时仍会连带
- 核颜色按 `group` 取调色板，组 0 不用于纠缠

调色板（原作 RGB，alpha 不透明）：

| group | 普通 | 高亮（可点爆） |
| --- | --- | --- |
| 非纠缠 / 0 | (33, 33, 33) | (77, 77, 77) |
| 1 | (83, 33, 180) | (130, 130, 180) |
| 2 | (180, 83, 33) | (180, 130, 130) |
| 3 | (33, 180, 83) | (130, 180, 130) |

### 5.8 坍缩表现

- 播坍缩音效
- 关掉碰撞、隐藏可移动箭头
- 核在约 0.2 秒内缩到 0 后隐藏
- 从盘面移除，不再参与胜负以外的模拟

## 8. 元进度、菜单、文案

### 8.1 解锁

对 `campaign` 按数组下标 `0 .. n-1` 扫描：

- 已在通关列表中：可进，使用通关色
- 否则若尚未分配完 3 个「未通关名额」：可进，使用未通关解锁色
- 否则：不可点

原作颜色（按钮 normal）：

- 通关：约 `(0.10, 0.63, 0.60)`
- 未通关可进：约 `(0.62, 0.90, 0.94)`

默认一次解锁 3 个未通关关，与原作 `unlockLevelCount = 3` 相同。Custom 全部用通关色且可进。

### 8.2 存档

- 单槽，逻辑名 `Player`（对齐原作 `accountName`）
- 只存：通关的 campaign 下标列表
- 不存当前关、不存 Custom、不存音量以外的设置也可另存
- 位置：Godot `user://`（例如 `user://account.cfg`），不要用零散的模拟 PlayerPrefs 键散落到各处

### 8.3 文案

所有玩家可见字符串走文案表，**第一版只发英文**，默认 locale `en`。禁止把句子写死在场景节点上。关卡 `name` 来自 JSON，不经过翻译表（专名冻结）。

| 键 | 英文 |
| --- | --- |
| `mode.campaign` | Campaign |
| `mode.custom` | Custom |
| `hud.left_steps` | Left Steps : {n} |
| `hud.completed` | Completed! |
| `hud.failed` | Failed! |

菜单关卡格上的数字是 `index + 1`，不是 `id`。

### 8.4 局内 HUD / 按钮

- 标题：当前关 `name`
- 剩余步数
- 胜负文案（进行中为空）
- 立即重开、回菜单（原作 Game 场景已有 Restart / Exit）

## 9. 表现与音频

### 9.1 画面

沿用原作精灵，不换视觉语言：

- 原子：`Nuclei`、`Orbit0` / `Orbit1` / `Orbit2`、`Orbit1_Dotted`、`Arrow`、`Neutron0`
- UI：静音 on/off、关卡格、重开/退出用的原图标可继续用

中子飞行时有拖尾（原作约 10 个残影、间隔 0.02s、透明度 0.5→0.1、缩放 0.8→0.2）。捕获时隐藏该中子拖尾。拖尾纯表现。

空格子显示位置标记（原作 `PositionMark`）。大地图缩小间距（见 4.1）。

### 9.2 音频

行为对齐原作，**文件可替换**：

- BGM：列表顺序播放，单曲不循环，播完切下一首，从头再来。原作六段为《库普兰之墓》乐章名；发行时必须使用有权使用的录音（公有领域/自有/已授权）。GDD 不指定 Hewitt 唱片
- 音效：原子坍缩播一次（原作 `bop2`）。最多同时 3 路 SE
- 一个全局音量；静音 = 音量 0，并切换按钮图

Unity 仓库里目前往往只有 `.meta`、没有 mp3 本体。落地时从本地原工程或合法源补文件，放到本仓库的 `assets/audio/`，不要把无权分发的录音提交到公开远程。

## 10. 关卡 JSON 合同

权威数据是版本化 JSON。`.tres` 只作运行时内存对象，不当事后真源。原 `Maps.json` 不在运行时解析。

建议路径：

```text
data/maps/campaign.json
data/maps/custom.json
```

每个文件是一个包。以后若要拆成一关一文件，关卡对象形状不变，只改包的引用方式。

### 10.1 包

```json
{
  "schema_version": 1,
  "id": "campaign",
  "maps": [ ]
}
```

- 加载时若 `schema_version` 大于游戏认识的版本：失败
- 小于当前：转换器或加载器做前向兼容（v0.1 只需要认识 1）
- 未知字段：忽略并警告
- `maps` 顺序 = 选关顺序 = 解锁扫描顺序

### 10.2 关卡对象

```json
{
  "id": "1-1",
  "name": "1-1 Click to Release",
  "width": 4,
  "height": 3,
  "steps": 1,
  "atoms": [
    {
      "x": 1,
      "y": 1,
      "type": "normal",
      "orbits": [["W", "NW", "NE", "E", "SE", "SW"]]
    },
    {
      "x": 2,
      "y": 0,
      "type": "entangled",
      "group": 1,
      "orbits": [["E"]]
    },
    {
      "x": 0,
      "y": 2,
      "type": "catching"
    }
  ]
}
```

字段：

| 字段 | 规则 |
| --- | --- |
| `id` | 包内唯一短 ID |
| `name` | 玩家可见标题，英文 |
| `width`, `height` | 正整数。奇数行少一格 |
| `steps` | 正整数 |
| `atoms[].x/y` | 必须落在合法格；同一关不能两原子同格 |
| `atoms[].type` | 第 6 节六选一 |
| `atoms[].group` | 仅纠缠类型必填，正整数；其它类型不得出现或必须忽略 |
| `atoms[].orbits` | 字符串数组的数组。长度 0（空捕获核）、1 或 2。每层方向为 `W|NW|NE|E|SE|SW`，允许重复（双层同向中子） |

空捕获核可省略 `orbits` 或写 `[]`。非捕获核若没有任何中子，加载失败（原作里没有这种正篇关）。

### 10.3 旧格式对照（仅转换器）

原原子：

```json
{ "x": 0, "y": 0, "type": 4, "group": 1, "neutrons": ["3", "1"] }
```

- `type` 缺省 0，`group` 缺省 0
- `neutrons` 每一项是一层，字符串里每个数字是一个中子
- 双层例：`["0", "3"]` → `orbits: [["W"], ["E"]]`

## 11. 模拟与模块边界

### 11.1 分层

| 层 | 职责 | 不得做的事 |
| --- | --- | --- |
| 数据 | 解析/校验 JSON，得到不可变 `MapData` | 生成节点、播动画 |
| 模拟 | 格子、原子运行时、中子飞行、胜负、步数 | 读输入设备、碰 Godot 物理、改 Sprite |
| 会话 | 把指针映射到模拟、2 秒胜负延迟、重开/切关 | 实现碰撞几何 |
| 表现 | 精灵、拖尾、轨道淡出、核缩放、HUD | 改步数或盘面 |
| 内容注册表 | `type` ID → 行为；方向 ID → 向量 | 写死 if-else 到会话里 |

局外 EditorPlugin 依赖**数据和模拟**，可以有自己的薄表现，禁止复制一份碰撞规则。

### 11.2 行为接口（概念）

每个原子类型模块至少回答：

- 指针按下：释放 / 开始拖 / 忽略
- 被核命中：是否释放
- 轨道是否接受捕获
- 捕获窗口结束变成什么类型

会话不要再写一套 `match type` 覆盖上述规则。

### 11.3 扩展原则（YAGNI）

现在就做：注册表、schema 版本、模拟/表现分离。

现在不做：模组加载器、脚本热重载、多模式基类、通用「关卡目标」插件。胜利条件冻死为「全部坍缩」。
